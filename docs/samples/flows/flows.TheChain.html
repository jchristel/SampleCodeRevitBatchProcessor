The Chain¶

Summary¶

The chain consists of a number of main workflows aimed at en mass family updates:

  • Reporting - of family properties :

    • REPORTING

    • SAVING MISSING FAMILIES

  • Changing - Specific families with specific actions :

    • RENAMING

    • CHANGE FAMILY CATEGORY

    • CHANGE FAMILY SUB CATEGORIES

  • Changing - All families with a default set of actions :

    • MODIFY DEFAULT

  • Reloading - nested families into host families : HowTo_ReloadFamilies.rst

    • RELOADING

Putting it all together¶

The PowerShell script theChain.ps1 in __A0_TheChain runs the flows switched on, in this order, passing each flow’s results on to the next:

  1. InitialReport : report on all families in the library

  2. FollowUpReport : report again on the families the last report could not process

  3. SaveMissingFamilies : save families missing from the library out of their host families

  4. ModifyDefault : modify families with the default set of actions

  5. RenameFamilies : rename families and the nested families in them, followed by a follow up report

  6. ChangeFamilyCategories : change family categories, followed by a follow up report

  7. RenameSubCategories : rename sub categories, followed by a follow up report

  8. ReloadFamilies : reload the changed families into their host families, followed by a follow up report on the reloaded families (or, with FullReportAfterReload, a full report and a follow up report)

# initial report only (also what runs without any switch)
powershell -ExecutionPolicy Bypass -File theChain.ps1 -InitialReport

# rename families, change categories, and reload everything that changed
powershell -ExecutionPolicy Bypass -File theChain.ps1 -RenameFamilies -ChangeFamilyCategories -ReloadFamilies

Get-Help .theChain.ps1 -Detailed lists all switches.

Each flow can also be run on its own with the start script in its _Script folder, e.g. _00_ReportFamilyData_ScriptstartReportFamilyData.ps1.

Run setupUsers.ps1 once before the first run (see SET UP).

Files passed between flows¶

Before a flow runs, theChain.ps1 copies its input files into the flow’s _UsersYOURUSERNAME_Input folder:

  • the report’s _Analysis_Current folder provides:

    • FamilyBaseDataCombinedReport.csv : to the rename and reload flows

    • FamilyCategoriesCombinedReport.csv : to the change family category and change sub category flows

    • HostsMissingFamilies.csv : to the save missing families flow

    • SecondProcessFamilies.csv : the families listed in it are reported on in a follow up report

  • the changed families lists (_OutputChangedFilesTaskList.csv) of the modify, rename, change category and change sub category flows run in the same run are combined into the reload flow’s _InputChangedFilesTaskList.csv, so every family changed in the run is reloaded. If none of them ran, the reload uses the changed families list already in its _Input folder.

  • a follow up report runs on the families in the changed families list of the flow before it, and its results are merged into the current reports.

A flow’s changed families list from a previous run is deleted before the flow runs, so it can’t be passed on as if it were new.

If a flow fails, The Chain stops, since the flows after it would work on incomplete data. A flow with nothing to process, for example without any change directives, is skipped and The Chain carries on.

Logs¶

  • The Chain: __A0_TheChainlogsYOURUSERNAME_TheChain_YYYY-MM-DD.log

  • each flow: _UsersYOURUSERNAME_OutputYOURUSERNAME_FLOWNAME_YYYY-MM-DD.log

Setting Up - The Chain¶

Requirements¶

  • Windows PowerShell 5.1 (part of Windows) or PowerShell 7

  • Revit Batch Processor

  • IronPython 3.4, used to run the pre and post processing scripts of each flow

  • the duHast library

Set up¶

  • copy the TheChain folder to your project folder location

  • edit __A0_TheChain\TheChainSettings.ps1:

    • chain_utils_path : the shared PowerShell helpers, Samples\PowerShell\BatchProcessorUtils.ps1 in this repository. The default works while The Chain is inside the repository. When The Chain is copied elsewhere, point this at a copy of that file.

    • iron_python_path : IronPython (default: C:\Program Files\IronPython 3.4\ipy.exe)

    • batch_processor_path : Revit Batch Processor (default: the per user install location, %LOCALAPPDATA%\RevitBatchProcessor\BatchRvt.exe)

  • in each flow’s _Script\settings.py:

    • DU_HAST_PATH : where the duHast library is installed

    • REVIT_LIBRARY_PATH : the root directory of your Revit family library (also in _01_X_RenameFamilies\_Script\utilModify.py and _02_ModifyFamilyLibraryReloadAdvanced\_Script\utilReload.py)

  • check the Revit version in the settings files in each flow’s _Users\_default\_Settings folder matches your required version:

    • “singleRevitTaskRevitVersion”: “Revit2024”

    • “batchRevitTaskRevitVersion”: “Revit2024”

  • run setupUsers.ps1 located in __A0_TheChain to create a user specific folder in each flow:

    powershell -ExecutionPolicy Bypass -File setupUsers.ps1

    It copies each flow’s _Users\_default folder to _Users\YOURUSERNAME and points the paths in the settings files in it at your user folder, wherever The Chain is located. Note: without a user specific folder the flows will not run.

    After moving or copying The Chain to another location, run it again with -RefreshSettings to update the paths in the settings files of user folders that exist already:

    powershell -ExecutionPolicy Bypass -File setupUsers.ps1 -RefreshSettings
