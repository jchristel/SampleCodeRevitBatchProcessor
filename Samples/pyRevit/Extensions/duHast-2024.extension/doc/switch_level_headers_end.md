# Switch Level Headers On (End)

## Overview
Switches on the level bubble headers at the end (1 end) of all levels visible in the current active view. This tool provides control over level annotation visibility at the terminus of level lines.

## Prerequisites
- Levels present and visible in the current view
- Active view with level elements
- Appropriate view type for level display

## Functionality
This tool:
- Activates level headers at the end position (1 end)
- Processes all levels visible in the active view
- Provides feedback on the number of levels processed
- Updates level display settings automatically

## Usage Steps
1. Navigate to the desired view containing levels
2. Click the "Switch Level Headers On (End)" button
3. Tool automatically processes all visible levels
4. Review console output for confirmation messages
5. Check view to verify level header visibility

## Level End Identification
- **0 End (Start)**: The beginning of the level line
- **1 End (End)**: The terminus of the level line
- This tool specifically targets the 1 end (end) position

## Processing Details
- Automatically detects all levels in active view
- Applies header visibility to each level individually
- Counts processed levels for user feedback
- Updates view display in real-time

## Input Requirements
- Active view containing level elements
- Levels must be visible in the current view
- Appropriate view type (plans, sections, elevations)

## Output
- Level headers displayed at end positions
- Console messages showing processing results
- Count of levels modified
- Status confirmation upon completion

## Feedback Messages
- Displays number of levels processed
- Shows detailed processing log
- Indicates if no levels are visible
- Confirms successful completion

## View Compatibility
Works with view types that display levels:
- Floor plans
- Ceiling plans
- Sections
- Elevations
- Area plans

## Automatic Processing
- No user selection required
- Processes all visible levels automatically
- Immediate visual feedback in the view
- Fast execution for any number of levels

## Error Handling
- Handles views with no visible levels
- Provides clear messages when no action is taken
- Graceful handling of level access issues
- Continues processing if individual levels fail

## Companion Tools
- Use with "Switch Level Headers On (Start)" for complete control
- Coordinate with level visibility settings
- Works alongside view template configurations

## Best Practices
- Use in views where level end points need emphasis
- Coordinate with project annotation standards
- Consider view scale when showing level headers
- Review level header placement after activation
- Use consistently across similar view types
- Balance with start headers to avoid clutter
